# hv-lore BIOS M60 v02.62 reconciliation

Date: 2026-08-15
Node: `hv-lore`
Platform: HP Z840 Workstation
Scope: firmware-state documentation and diagnostic handoff only

## Observed firmware update

Operator-provided HP Replicated Setup evidence confirms the host firmware was
updated from M60 v02.61 to M60 v02.62. The reviewed export reports firmware date
2024-01-04 and ME firmware 9.1.41.3024.

The first reviewed post-flash export retained UEFI boot, Legacy disabled,
Secure Boot enabled, All-UEFI Option ROM policy, PXE disabled, TPM enabled,
PCIe ACS enabled, main SATA AHCI, NUMA enabled, Hyper-Threading enabled, all CPU
cores enabled, Fast Boot disabled, and MMIO Assignment Mode Auto.

Post-flash drift requiring reconciliation was observed in AMT, VT-x, VT-d,
sSATA mode, QPI snoop mode, and power-loss behavior.

## Reconciled target profile

A full HP-format `HpSetup.txt` target profile was prepared with these deliberate
changes relative to the first reviewed M60 v02.62 export:

- AMT: Enabled -> Disabled
- VT-x: Disabled -> Enabled
- VT-d / IOMMU: Disabled -> Enabled
- sSATA Controller Mode: RAID -> AHCI
- QPI Snoop Mode: Early Snoop -> Home Snoop
- Power state after power loss: Previous State -> Power On

The profile intentionally leaves MMIO Assignment Mode Auto, TCG event log
SHA-1, the exported UEFI boot order, PCIe slot speeds Auto, and PCIe
bifurcation Auto.

Profile SHA256:

```text
dcfc24eea7eb472b76419525d201d3d5d5bbc5f1150181355c2fd200fa4699b5
```

The historical five-second POST delay is not represented in the HP export
surface and must be verified manually rather than inserted as a synthetic
Replicated Setup field.

## Validation boundary

M60 v02.62 is proven installed, but the reconciled target profile is not yet a
proven-applied canonical firmware artifact. A fresh HP Replicated Setup export
is required after final save/reboot to prove setting acceptance, including the
resulting ME firmware mode after AMT is disabled.

The intermittent warm-reboot freeze around `Loading initial ramdisk ...` /
initramfs persists after the M60 v02.62 firmware update. The BIOS flash therefore
did not resolve the defect.

The next independent diagnostic is a persistent Debian installation on a
separate USB device, booted on hv-lore with its own EFI/GRUB/kernel/initramfs and
persistent root/log state, to separate platform/firmware/device reset behavior
from the installed Proxmox boot chain.
